# Tom 的写作风格

写作前阅读与当前主题最相关的历史文章。将本文作为共同约束，不机械复制旧文的结构、句式或排版。

## 写作立场

- 从 Tom 真实提供的经历、观察、问题或判断出发。没有相关素材时主动询问，不编造第一人称经历。
- 将文章写成一次真实的思考、复盘或分享，不写成居高临下的教程。
- 可以给出明确判断，但要交代判断成立的依据、适用前提和仍不确定的部分。
- 保留真实的犹豫、变化和失败。不要为了让故事完整而美化过程。
- 区分 Tom 的判断、外部观点和已验证事实，不把三者混在一起。

## 内容组织

- 让全文围绕一个清晰的核心问题或核心表达推进。
- 按内容本身的逻辑安排结构，不套固定文章模板。
- 建立清楚的推导关系：为什么关注这个问题、观察到了什么、如何理解、最终得到什么判断。
- 每一节只承担清晰的作用。删除不推动论述的信息、重复结论和无意义的过渡。
- 先把问题和结论讲清楚，再补充必要的技术细节。
- 使用具体经历、案例、数据或设计选择支撑抽象判断。
- 当事实或调研结果与最初想法冲突时，保留这种冲突，不强行维护原结论。

## 表达方式

- 使用自然、直接的中文，保持口语感，但不要松散。
- 保持朴实、克制、具体。优先讲清事实、过程和判断，不把普通实践包装成重大突破，也不为了增强气势夸大价值。
- 优先使用短句和常见词。能直接说清楚时，不使用抽象名词或复杂包装。
- 把复杂技术概念翻译成读者能理解的因果关系、对比或具体例子。
- 技术术语保留行业常用英文，如 Agent、Context、Memory、Harness；不要为了中文化而生硬翻译。
- 首次出现不熟悉的术语时，用一句话解释它在本文中的意思。
- 可以使用第一人称，但不要每一段都以“我认为”“我觉得”开头。
- 可以使用“坦率地说”“务实地说”“换句话说”等自然转折，但只在语义需要时使用，不把它们当作文风装饰。
- 让关键判断足够明确。不要用大量保守措辞把结论稀释掉，也不要下没有依据的绝对结论。

## 使用外部信息

- 引用外部观点是为了支撑、挑战或定位自己的判断，不做资料堆砌。
- 提到外部观点后，说明 Tom 对它的理解、认同、补充或分歧。
- 为事实、数据和引用提供能够直接支持该表述的来源链接。
- 不使用未经核验的数字，不根据搜索摘要推断原文结论。
- 不为了显得信息丰富而加入与核心表达关系不大的研究结果。

## 排版

- 使用标题表达内容，不使用“背景介绍”“核心内容”等空泛标题。
- 一个 `##` 小节较长且包含多个内容层次时，使用有实际含义的 `###` 小标题分层；内容单一时不要为了排版硬拆。
- 只在信息确实并列时使用列表。
- 只在对比关系通过表格明显更清楚时使用表格。
- 用加粗突出全文最关键的少量判断或结论，帮助读者快速抓住重点；不要整段加粗，也不要为每一节机械添加。
- 谨慎使用引用块、下划线、ASCII 图和代码块，由内容需要决定。
- 保持中英文之间的空格、术语大小写和标点风格在全文一致。

## 避免 AI 写作痕迹

- 不使用“在当今快速发展的时代”“随着技术不断发展”“值得注意的是”“综上所述”等空泛套话。
- 不堆砌“赋能、颠覆、革命性、全方位、深度解析”等营销词。
- 不把每个部分都写成相同长度、相同句式或严格对称的结构。
- 不为了形式完整而凑出固定数量的观点、步骤或展望。
- 不连续使用“不是……而是……”“不仅……更……”等相同句式。
- 不在结尾机械复述全文，也不强行升华行业意义。
- 不模仿或重复历史文章中的标志性句子，让表达服从当前内容。

## 完稿检查

完成后检查：

1. 核心问题和核心表达是否清楚？
2. 文章是否沿着一条可以跟随的逻辑线推进？
3. 是否存在重复、空泛、跳跃或过度解释的段落？
4. 抽象判断是否有真实经历、事实或例子支撑？
5. Tom 的观点、外部观点和事实是否清楚区分？
6. 是否编造了 Tom 未提供的经历、感受或判断？
7. 技术内容对目标读者是否足够通俗？
8. 较长小节是否在需要时使用 `###` 分层，关键判断是否被少量加粗突出？
9. 是否存在不必要的包装、营销腔或 AI 套话？
10. 读起来是否像 Tom 在认真讲清楚一件自己真正思考过的事情？
