最近我把自己的 AI 开发工作台搬到了云端。

现在不管手边是手机、平板，还是一台临时使用的电脑，我都可以打开浏览器，进入一个正在做的产品的工作区，继续之前的工作。需要让 Agent 推进任务时就直接对话，需要看代码时可以打开文件，需要自己处理一些细节时也能进入 Terminal。做完以后，构建和部署也都在同一台服务器上完成。

实现这件事的工具叫 [CloudCLI](https://github.com/siteboon/claudecodeui)，也就是原来的 Claude Code UI。这篇简单分享一下，我为什么会需要它，以及现在是怎么使用它的。

![CloudCLI 中的项目工作区和 Session 管理](https://linfeng-blogs-material-1345080753.cos.ap-singapore.myqcloud.com/blog/2026/08/cloudcli-ai-native-development-anywhere/cloudcli-workspaces.png)

## 从随时给 Agent 发消息开始

最早让我感受到「随时随地使用 Agent」的产品是 OpenClaw。

OpenClaw 可以常驻在云端，再通过飞书、Telegram 等通讯软件和人交互。这样一来，不需要坐在电脑前，也可以直接给 Agent 发消息，让它查资料、整理内容、处理文件或者执行一些定时任务。

我之前也用 [OpenClaw + 飞书搭过一套博客运营系统](/2026/03/15/agent-product/openclaw-feishu-blog-automation/)。到现在，做内容创作时我仍然会使用这种方式。比如走在路上突然有一个灵感，我可以直接在飞书里用语音说出来，让 Agent 帮我记录到个人知识库。飞书的语音输入很好用，这种场景下比打开电脑自然得多。

但当我开始同时做多个产品时，只通过通讯软件和 Agent 交互就不太够了。

## 做产品时，我需要的不只是一个聊天框

内容记录和很多自动化任务，通常只要把需求说清楚，再接收结果就可以了。产品开发不太一样。

我需要在多个工作区之间切换，每个工作区里又有自己的代码、文档和历史 Session。有时候我要浏览文件，确认 Agent 到底改了什么；有些非常细的页面和代码调整，我会想自己直接修改；偶尔遇到构建、Git 或部署问题，也还是需要进入 Terminal 看一眼。

飞书和 Telegram 本质上仍然是通讯工具。它们可以让我远程指挥 Agent，但没有一个方便的入口让我查看和操作服务器上的完整文件系统。任务简单时这不是问题，开发一个需要反复调整的产品时，这个限制就会变得很明显。

后来 Claude Code、Codex 和 Cursor 等产品也陆续提供了各自的云端协同能力。它们都能解决一部分问题，但入口分散在不同产品里。如果一个工作区里只使用一种 Agent Runtime，这样没有什么问题；但我的实际使用习惯不是这样。

我会根据任务选择不同的 Agent。有时用 Claude Code，有时用 Codex，也可能使用 Cursor 或 OpenCode。代码和项目明明都在同一个工作区里，如果每换一个 Agent，就要换一套端侧入口，使用起来会很割裂。

所以我想找的其实很简单：**一个以工作区为中心的云端开发界面。Agent 可以换，但项目、文件和 Session 都从同一个地方进入。**

## CloudCLI 把这些入口放到了一起

[CloudCLI](https://github.com/siteboon/claudecodeui) 是一个开源的 Web UI，可以在桌面端和移动端使用。它最早叫 Claude Code UI，但现在已经不只支持 Claude Code。项目目前支持 Claude Code、Codex、Cursor CLI、Gemini CLI，近期也加入了 OpenCode。

它提供的功能基本覆盖了我做产品时会用到的几个入口：

- 按项目管理不同的工作区；
- 在每个工作区中新建和继续 Session；
- 选择不同的 Agent Runtime 和模型；
- 浏览并编辑服务器上的文件；
- 使用内置的 Shell Terminal；
- 查看 Git 状态、提交代码和切换分支。

我把它部署在云端，让代码仓库、Agent Runtime 和开发环境都留在服务器上。手机、平板和电脑只是进入这套环境的不同入口。

现在如果有一个新的产品想法，我会先在对应的工作区里新建 Session，和 Agent 梳理需求，再继续做产品设计和实现。如果同时在做几个产品，就为每个产品保留独立的工作区和会话。下次打开时，不需要重新寻找代码路径，也不需要回忆上一次在哪个工具里聊到哪里。

截图左侧就是我现在的工作区。不同项目分别放在不同目录里，同一个项目下面又可以保留多次对话。比如这次有一个新的博客主题，我就进入博客仓库，新开一个 Session；要继续调整另一个产品，则直接切换到它自己的工作区。

对我来说，文件和 Terminal 也很重要。多数时候 Agent 可以自己完成开发任务，但我仍然经常需要看看具体文件，或者亲自改一个很小的细节。如果遇到特殊情况，也能直接在浏览器里进入 Shell，而不用想办法通过聊天消息绕一圈。

CloudCLI 的移动端 Web 体验也不错。在手机上长时间写代码当然谈不上舒服，但用来发起任务、查看进度、浏览文件和处理小修改已经足够。很多时候我只是临时有一个想法，或者想确认 Agent 的执行结果，不需要为此回到固定的电脑前。

## 我的开发环境不再绑定一台电脑

现在我的使用方式很朴素。

灵感记录、个人知识库和内容创作，我还是更喜欢用飞书作为入口。它随手就能打开，语音输入也很舒服，很适合把脑海里刚出现、还不完整的东西先留下来。

真正开始做产品时，我会打开 CloudCLI。因为这时我需要的不只是和 Agent 聊天，还需要进入具体的工作区，查看文件，切换 Session，偶尔亲自修改代码或者执行命令，最后把产品部署上线。

它们解决的是两种不同的使用场景，我也没有打算只保留其中一种。只是有了 CloudCLI 以后，我做产品不再被某一台电脑或者某一个 Agent 的客户端绑住了。只要能打开浏览器，我就能回到自己的开发环境，继续上次没有做完的事情。
