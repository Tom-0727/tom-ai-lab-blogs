两个多月前，我在[《OpenClaw 不是终点》](/2026/04/08/agent-engineering/openclaw-is-not-the-end/)里下了个决定：不在别人的框架上改了，自己造一个 [Long-Run Agent Harness](https://github.com/Tom-0727/long-run-agent-harness)。那篇文章的结尾，我还挺乐观地写着"先让 Agent 能长期运行并持续变强"。

现在，我把它按下了暂停。

这篇不是成功故事，而是一次诚实的止损记录。**我想认真讲清楚：当初想要什么、撞到了哪堵墙、为什么停、以及停下来之后真正沉淀下来的是什么。** 暂停不等于失败——但前提是你得诚实地知道自己停在哪、为什么停。

## 当初的两个目标

动手之前，我给这个项目设了两个目标，一个务实，一个有点野心。

1. **效率**：借助 AI 自主化工作，加速从"想法"到"现实"的链路，把我自己的时间解放出来，投到更值得花的地方——更自由的思考、更靠近业务价值的判断。
2. **影响力**：说实话，我幻想过并肩 OpenClaw。我当时深信"长期运行的 Agent"是下一个热潮，想在这波里留下点自己的东西。

第一个是工具视角，第二个是赛道视角。后面会看到，**这两个判断一个被现实修正，一个被大厂印证——但都不是以我预想的方式。**

## 第一堂课：把 Human 从 loop 里拿掉，质量就塌了

这是最主要、也最让我意外的一课。

我原本的设想是：让 AI 尽可能自主地往前跑，急剧压缩 Human in the Loop，这样才能真正"解放时间"。但真正跑起来之后，**自主工作的 AI 一旦缩减人类介入，产出的质量稳定性就变得极差，非常容易不符合预期。**

更微妙的是交互方式本身的漂移。当我面对一个高度自主的 Agent，注意力会非常自然地滑向"形而上"那一端——去和它对齐抽象概念、目标、方向。这部分对得很顺。但细节层面，完全没法任由它自由发展。它会在我没盯着的地方，把一个 60 分的东西当成做完了。

| 交互层 | 和自主 Agent 的实际体验 |
| --- | --- |
| 抽象层（目标、概念、方向） | 对齐很顺，讨论甚至挺愉快 |
| 细节层（具体实现、取舍、质量） | 一旦放手就走偏，而且偏得很隐蔽 |

讽刺的是，这正好反咬了我自己。在 OpenClaw 那篇里，我写过一句判断：现阶段的 Agent"执行层面已经很强了，但判断层面还需要人类校准"。我当时把它当成一个设计原则写下来，转头却想在新项目里把这层校准压缩掉。**换句话说，HITL 不是可以无脑削减的成本，它本身就是质量的一部分。** 缩减它的代价不是线性的，是断崖式的。

## 第二堂课：大厂果然下场，而且做得更系统

另一件事，是我那个"赛道判断"被验证了——只不过是被 Anthropic 和 OpenAI 验证的。

就在这段时间，Claude Code 上线了 [`/loop` 和 `/goal`](https://code.claude.com/docs/en/agent-sdk/agent-loop)，让你定义一个持续目标、让模型在循环里自己跑到满足条件为止；OpenAI 的 Codex 也上了 [`/goal`](https://developers.openai.com/codex/use-cases/follow-goals)，内部把这套循环叫 "Ralph Loop"。这正是我想做的"长期运行、自主推进"那件事，被官方用更系统、更可靠的方式做了出来。

我深信这是热潮——这个判断没错。但热潮一旦被官方接管，**个人从零自建一个 harness 的窗口，就在快速收窄。** 这不是坏事。一个方向同时被印证又被超越，本来就是个人探索的常态。我得诚实承认：我的价值不在于再手搓一个 `/loop` 出来。

## 为什么按下暂停

停下来的原因有两个，主次分明。

1. **最主要的是产出不可靠**，也就是第一堂课的直接后果。一个我自己都没法稳定信任其产出的系统，谈不上"解放时间"——它只是把我盯执行的时间，换成了盯它有没有跑偏的时间。
2. **其次是时间窗被现实挤掉了。** 工作上来了一个倒排的项目，急剧压缩了我自由探索的时间。在一个 ROI 还没跑正的副线上，我没法继续硬投。

我想说清楚：这是一次基于 ROI 和时间窗的现实选择，不是判定它走进了技术死路。**暂停≠放弃**，只是此刻不值得继续硬推。

## 暂停之后，真正沉淀下来的

postmortem 最该做的，是盘点资产。**即使主目标没达成，这个项目仍然给我留下了三样实在的东西。**

<u>胶水编程的价值</u>。很朴素，但被反复验证：把现成的能力（SDK、协议、调度、通知）用胶水代码黏成一个能跑的系统，这种工程能力本身就是有用的，迁移性也很强。

<u>对 cc sdk 和 codex app server protocol 的实操经验</u>。这个项目逼我把 Claude Code SDK 和 Codex 的 app server protocol 真正用了一遍、踩透了。这部分手感后来直接喂到了别的工作里，没有白练。

<u>中控平台的便利</u>。我给 harness 做了一个中控平台，一个意外的好处是它能很方便地绕开 Claude 的登陆问题，让我随时随地用上。这里要诚实设限：自从 Codex 出了移动端适配，这个方案的价值被挤兑了不少；但在服务器常驻这个场景下，它依然合适。

## 我学到的

把这次暂停浓缩成几句，给现在的自己，也给可能在做类似事情的你：

- **HITL 是质量的来源，不是效率的敌人。** 想靠压缩人类介入来提速，大概率会先被质量塌方反噬。真正该压缩的不是"人介入的次数"，而是"人介入的成本"——这是两回事。
- **个人探索被大厂印证又超越，是常态，不是挫败。** 判断对了值得高兴；窗口被接管，就把精力挪到别人还没做、或者只有你能做的地方去。
- **就算项目停了，工程肌肉和可复用资产会留下来。** 胶水能力、对 SDK / 协议的手感、能随时随地干活的基础设施——这些都不会因为暂停而清零。

这些都只是我此刻的判断，不代表自主 Agent 没有未来，也不代表我不会重启它。它是"现在的我 + 现在的产出质量 + 现在的时间窗"三者交叉下的一次止损。等其中某一项变了，我大概会把它重新打开。

如果你也在自建 Agent Harness、或者正纠结 Human in the Loop 到底该放在哪，欢迎交流。慢慢来。
